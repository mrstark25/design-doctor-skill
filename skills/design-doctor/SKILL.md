# Design Doctor

Turn UI that "works" — or a live URL — into UI that looks **deliberately designed by a 10-year
veteran**, not generated by AI. Diagnose, commit to a direction, rebuild with craft, serve, verify.

This skill exists because the default AI aesthetic (dark + purple, aurora blobs, gradient text,
glowing glass cards) is instantly recognizable and reads as cheap. Design Doctor's whole job is to
**avoid that** and produce something specific, restrained, and credible.

## When To Use

- "Redesign this landing page / make it not look AI-generated"
- "Here's a URL — rebuild it better": fetch it, redesign it, serve it
- "Audit my pages and upgrade them one by one"
- modernizing a bland or template-looking interface

## The Non-Negotiables (read `ANTI-AI.md` in full before writing any CSS)

1. **Commit to a specific visual direction** (see `DIRECTIONS.md`). "Dark + an accent" is not a
   direction. Editorial-Swiss, brutalist, light luxury, etc. — pick one and execute it fully.
2. **Ban the AI tells**: no aurora/gradient blobs, no gradient-filled headline text, no glowing
   glassmorphic cards, no rainbow chips, no system-sans-only, no pulsing-everything. (`ANTI-AI.md`)
3. **Real typography**: a deliberate pairing (e.g. a characterful display + a grotesk), with a
   true type scale, tabular numbers for data, and micro-typographic detail. Not the default stack.
4. **Visible structure**: hairline rules, a grid you can feel, numbered section indices, generous
   and *intentional* (non-uniform) whitespace.
5. **One disciplined accent**, used as ink — not as glow. Honor brand color by execution, not by
   reaching for gradients.
6. **A signature element + a real product visual.** Every product page needs one designed
   centerpiece (a swap panel, a live data table/screener, a routing diagram) — not just prose.
7. **Depth & motion as craft, not decoration**: soft shadows, layered surfaces, count-ups,
   draw-on-load diagrams — subtle, purposeful, and compositor-friendly.
8. **CONTENT IS NEVER HIDDEN WAITING ON JS.** This is the rule that bit us hardest. Do **not** gate
   content behind a JS scroll-reveal (`opacity:0` until an IntersectionObserver fires). Above-the-
   fold especially must render immediately. Animate **from a visible baseline** with pure CSS, or
   not at all. (`WORKFLOW.md` §6)
9. **CHANGE DESIGN ONLY — NEVER THE FUNCTIONAL PART.** This is a *visual* redesign. Touch CSS and
   presentational markup only. Do **not** alter or remove logic, event handlers, data fetching, API
   calls, routing, state, form behavior, or the DOM hooks the app depends on (ids, classes,
   `data-*`, element structure that JS queries). On a real app, grep for those hooks first and
   restyle *around* them. If a visual change would require a behavioral change, stop and ask.
   (`WORKFLOW.md` §4 — Preservation contract)
10. **ONE RESPONSIVE CODEBASE — DESKTOP AND MOBILE AT ONCE.** Never a separate mobile version. Build
    fluid, mobile-first layouts that adapt at 320 / 375 / 768 / 1024 / 1440 with no horizontal
    overflow, readable type, and ≥44px touch targets. Verify both ends before declaring done.
    (`WORKFLOW.md` §9)

## Workflow (full detail in `WORKFLOW.md`)

1. **Acquire** — for a URL, fetch it and extract *all* content verbatim (headline, sections, copy,
   CTAs, stats, nav, footer). For existing code, read it fully. Stay content-accurate.
2. **Diagnose** — score each surface against `RUBRIC.md`; fan out the `design-auditor` agent for
   multi-surface audits. Lead with a scored table, worst-first.
3. **Direction** — pick ONE direction from `DIRECTIONS.md`; define the token set (color, type
   pairing, scale, spacing, radius, motion) once, up front, in a tokens file.
4. **Rebuild** — implement surface-by-surface using the proven primitives in `reference/`. Build
   the signature visual. Preserve behavior, routing, data, and copy.
5. **Serve & verify** — make it runnable (relative asset paths + cache-bust query) and confirm it
   serves; validate JS (`node --check`) and CSS (brace balance); state how it was checked.
6. **Iterate** — present before→after, take the rating, push the weak surfaces further.

## Serving & Cache (lessons learned — see `WORKFLOW.md` §7)

- Use **relative** asset paths (`./styles.css`) so the page works both via a server and via
  double-click (`file://`). Absolute paths (`/styles.css`) break under `file://`.
- Add a **cache-bust query** (`./styles.css?v=N`) and bump it on every change; tell the user to
  hard-reload. Stale CSS/JS is the #1 reason "your change isn't showing."
- Serve statically (`python3 -m http.server PORT`) and curl for HTTP 200 before claiming it works.

## Output Discipline

- Lead with the diagnosis table, then the direction, then the build. Don't paste walls of CSS.
- After building, state verification results (serves 200, JS/CSS valid, what was checked).
- Track surfaces with TodoWrite so the user can steer mid-redesign.

## Supporting Files

- `ANTI-AI.md` — banned patterns + required qualities. **The most important file.**
- `DIRECTIONS.md` — committed directions, each with a token + type + component spec.
- `WORKFLOW.md` — the detailed procedure, the no-hidden-content rule, serving/caching.
- `RUBRIC.md` — 10-point scoring, bands, definition of done.
- `reference/editorial-swiss.css` — proven, reusable primitives (tokens, type, hairlines,
  buttons, ticker, data table, figures, no-reveal animation pattern, reduced-motion).
- `reference/patterns.md` — copy-adaptable recipes for the signature components.
- `reference/starter.html` — a minimal page wired to the reference CSS.
