# 3D & WebGL (Three.js) — disciplined depth, never decoration

Read `ANTI-AI.md` first. 3D is powerful and **dangerous for this skill**: the lazy version of 3D —
a drifting particle nebula, a rotating gradient blob, a glassy floating torus behind the hero — is
*itself* a top-tier AI tell. This file is the contract for using Three.js so it reads as craft, not
as a generated demo. Default to **no 3D**; add it only when it earns its place.

## When 3D is justified (and when it is not)

Use it when depth communicates something real:

- **A product centerpiece as an object** — a token/coin, a routing mesh, a network/graph, a device,
  a chart that genuinely benefits from a third axis. The thing the page is *about*, rendered.
- **Restrained spatial depth** behind an editorial hero — a sparse, gridded depth field that
  parallaxes to the pointer. Instrument-like, monochrome, barely there.
- **A data surface in 3D** when 2D can't show it — a surface plot, a 3D scatter, an orderbook depth
  wall. Only if the extra dimension carries information.

Do **not** add 3D when:

- It's purely behind text as "ambience" (that's the aurora-blob tell in WebGL form).
- The page is content/marketing copy that a clean 2D layout serves better.
- It would be the *only* way the centerpiece is communicated (fails the fallback contract below).
- You can't afford the perf budget on the target devices.

## The fallback contract (NON-NEGOTIABLE — extends rule #8)

The `<canvas>` is **additive enhancement only**. The page must be complete and on-message with WebGL
disabled, JS off, the CDN blocked, or reduced-motion on.

- Every 3D centerpiece sits **on top of / beside a real DOM or SVG element** that already conveys the
  point (a static product visual, a diagram, a heading + figures). If the canvas never loads, that
  element is what the user sees — and it must look finished, not empty.
- **Never** gate copy, nav, CTAs, stats, or any content on the 3D layer rendering.
- The canvas must have explicit/﹡intrinsic dimensions and a CSS background (or sit over one) so there
  is **no layout shift and no blank rectangle** before/if it boots.
- `reference/three-scene.js` enforces this: it returns `null` and does nothing when WebGL is absent,
  imports Three.js only on viewport-intersect, and renders a single static frame under reduced-motion.

## 3D-specific AI tells — BANNED

These are the WebGL fingerprints of generated UI. If you reach for one, stop.

1. **Particle nebula / starfield drifting behind the hero** — the aurora blob, reincarnated. Banned.
2. **Rotating gradient blob / iridescent metaball / glassy torus-knot** with bloom. Banned.
3. **Rainbow / iridescent shader materials** — color must come from the page tokens and carry meaning.
4. **Bloom + chromatic aberration + film grain stacked** as "cinematic" default post. Banned.
5. **Auto-spinning everything forever** with no interaction logic. Motion must have intent.
6. **A full-bleed canvas the text floats on** with no fallback and no information. Banned.
7. **Unpinned CDN / 600kb+ of libraries** loaded eagerly on a landing page. Banned (lazy + pinned).

## Craft requirements — a 3D surface must show most of these

1. **Token-driven color** — the scene reads `--ink`, `--bg`, `--faint` etc. so it matches the
   committed direction. Monochrome + ONE accent, never invented neon.
2. **The hairline aesthetic in 3D** — prefer edges/wireframe/points over heavy shaded solids; depth
   from line weight and layering, not glow.
3. **Purposeful, pointer-aware motion** — subtle parallax/rotation that responds to the user, eased,
   slow. Not a perpetual demo spin.
4. **Honest performance** — DPR capped (~1.75), low geometry counts, paused offscreen and on hidden
   tabs, disposed on teardown. Target a steady 60fps on a laptop; degrade gracefully on mobile.
5. **Reduced-motion path** — one composed static frame, no animation, no pointer hijack.
6. **No layout shift** — reserved dimensions, transparent renderer over a real CSS background.

## Performance budget

- Three.js core only (~150kb gzip via ESM), **lazy-imported on intersect**, version-**pinned**.
- Cap `devicePixelRatio` at ~1.75; antialias on but keep triangle/point counts modest.
- `requestAnimationFrame` paused when the canvas is offscreen and when `document.hidden`.
- No heavy post-processing pipeline on a landing page. If you add bloom, justify it and measure.
- Fully dispose geometries/materials/renderer and remove listeners on teardown (SPA route changes).

## Accessibility

- The canvas is decorative: `aria-hidden="true"` on it, with the meaning carried by the labelled DOM
  fallback beside/under it.
- Honor `prefers-reduced-motion` (the module does — static frame only).
- Never trap focus or scroll in the canvas; pointer interaction is enhancement, never required.

## How to use `reference/three-scene.js`

Declarative (auto-wires any opted-in canvas):

```html
<!-- The fallback IS the figure; the canvas only adds depth over it. -->
<figure class="centerpiece">
  <canvas data-dd3d="wireframe" data-accent="--ink" aria-hidden="true"></canvas>
  <!-- real, visible-by-default fallback content here (SVG/markup) -->
</figure>
<script type="module" src="./three-scene.js?v=1"></script>
```

Programmatic (e.g. inside a component, with cleanup on unmount):

```js
import { mountScene } from './three-scene.js';
const handle = mountScene(canvasEl, { scene: 'lattice', accent: '--ink', density: 420 });
// on route change / unmount:
handle?.destroy();
```

Scenes provided: `wireframe` (a slow-turning edge-rendered solid — a product object) and `lattice`
(a sparse, gridded depth field that parallaxes to the pointer). Both read the page tokens, both are
reduced-motion safe, both are pure enhancement. Add new scenes to the `SCENES` map in the module
following the same `{ object, tick(t, pointer) }` shape — and keep them token-driven and cheap.

## Self-audit before declaring a 3D surface done

- [ ] With WebGL off / JS off / CDN blocked, is the page still complete and on-message?
- [ ] Is there a real, visible-by-default DOM/SVG fallback under the canvas (no blank rectangle)?
- [ ] Does the scene use the page's tokens — monochrome + one accent, no rainbow/iridescence?
- [ ] Is it none of the banned tells (nebula, gradient blob, bloom-stack, perpetual spin)?
- [ ] Is Three.js lazy-loaded, version-pinned, and paused offscreen/hidden?
- [ ] Reduced-motion → static frame only? `aria-hidden` on the canvas?
- [ ] No layout shift; steady framerate on a laptop; graceful on mobile?
